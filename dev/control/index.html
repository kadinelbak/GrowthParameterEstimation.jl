Handing fitted models to control tools

GrowthParameterEstimation identifies and qualifies growth models; it does not solve optimal-control problems. Mature Julia packages already do that (for example ModelPredictiveControl.jl for nonlinear MPC, or JuMP / InfiniteOpt.jl for direct optimal control). The control API is the handoff between the two: it turns a fitted model into the standard f(x, u, p) form and carries its bootstrap parameter sets so a schedule can be checked for robustness.

The input replaces the exposure

Registered models take an exposure function, ode!(du, u, p, t, exposure). A ControlModel replaces that exposure with a control input u: exposure(t) returns u[1] for a single-input model and the input vector u for a model with several inputs. Nothing about the fitted model changes.

Building a ControlModel

using GrowthParameterEstimation

spec = get_model("logistic_linear_kill")
fit = fit_model(spec, t, y, 1.0)

cm = controlled_model(spec, fit.params; input_names = [:dose])

Any right-hand side in the package convention works, including models fitted with run_joint_fit. Attach bootstrap parameter sets directly from bootstrap_joint_fit:

boot = bootstrap_joint_fit(model!, datasets, u0, p0; bounds = bounds, n_bootstrap = 200)

cm = controlled_model(model!, boot.fit.params;
    n_states = 2, n_inputs = 2,
    state_names = [:S, :R], input_names = [:dose, :fasting],
    param_samples = boot,
    observable = (x, p) -> [x[1] + x[2], x[2] / (x[1] + x[2])],
    output_names = [:total, :resistant_fraction])

Declare autonomous = false if the right-hand side uses t directly. Schedules built on such models assume the input started at t = 0.

Checking a schedule

InputSchedule holds a piecewise-constant schedule, the form a control solution takes when doses change only at decision times. simulate_schedule replays it with the full ODE solver (stopping at every dose change), and schedule_ensemble replays it on the point estimate and every bootstrap set.

sched = InputSchedule(0:2:12, [0, 0, 0, 0.62, 1.47, 1.47, 0])
out = simulate_schedule(cm, x0, sched, 0:0.5:14)

runs = schedule_ensemble(cm, x0, sched, 0:0.5:14)
finals = [r.outputs[1, end] for r in runs]    # spread of the final burden

Exporting

control_model_summary(cm) returns names, dimensions, estimates, samples and metadata as plain data; save_control_model(cm, path) writes it as JSON for tools in other languages.

API

GrowthParameterEstimation.Control.ControlModel — Type
ControlModel

A fitted model packaged for optimal-control and model-predictive-control tools.

GrowthParameterEstimation does not solve control problems itself. A ControlModel is the handoff: it turns a fitted right-hand side into the standard f(x, u, p) form those tools expect, and carries the point estimate and any bootstrap parameter sets so schedules can be checked for robustness.

The control input u replaces the package's exposure function. Inside the right-hand side, exposure(t) returns u[1] when the model has one input and the whole input vector u when it has several. Build one with controlled_model.

Fields

  • name::String: Model name
  • rhs!::Function: Right-hand side in the package convention (dx, x, p, t, exposure)
  • n_states::Int, n_inputs::Int: State and input dimensions
  • state_names, input_names, param_names: Labels for states, inputs and parameters
  • params::Vector{Float64}: Point estimate
  • param_samples::Vector{Vector{Float64}}: Bootstrap (or other) parameter sets; may be empty
  • observable::Function: Output map (x, p) -> y::Vector
  • n_outputs::Int, output_names: Output dimension and labels
  • autonomous::Bool: true when the right-hand side does not depend on t directly
  • metadata::Dict{Symbol,Any}: Free-form provenance (source model, fit, units)

GrowthParameterEstimation.Control.controlled_model — Function
controlled_model(rhs!, params; n_states, n_inputs = 1, kwargs...) -> ControlModel
controlled_model(spec::ModelSpec, params; kwargs...) -> ControlModel

Package a fitted model for control tools.

The first form takes any right-hand side in the package convention rhs!(dx, x, p, t, exposure) (the same convention as registered models), such as the model passed to run_joint_fit. The second form takes a registered ModelSpec and its fitted parameter vector (for example fit_model(...).params).

Keyword arguments

  • param_samples = nothing: Bootstrap parameter sets: a vector of vectors, or a bootstrap_joint_fit result (its estimates are used)
  • name, state_names, input_names, param_names: Labels (defaults are generated)
  • observable = nothing: Output map (x, p) -> y or x -> y; default outputs all states
  • output_names = nothing: Output labels
  • autonomous = true: Declare whether the right-hand side ignores t. Control schedules built on non-autonomous models assume the dose started at t = 0.
  • metadata = Dict(): Provenance to carry along (units, source fit, stage)

Examples

spec = get_model("logistic_linear_kill")
fit = fit_model(spec, t, y, 1.0)
cm = controlled_model(spec, fit.params; input_names = [:dose])

f = control_rhs(cm)          # f(x, u, p, t) -> dx
F = discrete_dynamics(cm; dt = 2.0) # x_next = F(x, u, p)

Out-of-place continuous-time dynamics. The returned vector takes the promoted element type of x, u and p, so it can be differentiated with ForwardDiff.

GrowthParameterEstimation.Control.mpc_functions — Function
mpc_functions(cm::ControlModel) -> NamedTuple

Dynamics and output functions in the (ẋ, x, u, d, p) / (y, x, d, p) convention used by nonlinear MPC packages such as ModelPredictiveControl.jl (NonLinModel(f!, h!, Ts, nu, nx, ny; p = p)). d (measured disturbances) is accepted and ignored.

Returns (f!, h!, nx, nu, ny, p), where p is the point estimate.

source
GrowthParameterEstimation.Control.discrete_dynamics — Function
discrete_dynamics(cm::ControlModel; dt, substeps = 20) -> (x, u, p = cm.params, t0 = 0.0) -> x_next

Discrete-time transition map for a zero-order hold: the state after holding the input u constant for dt, integrated with substeps fixed classical RK4 steps. This is the step map used by direct shooting and MPC solvers. It allocates no solver state and differentiates cleanly with ForwardDiff, so Jacobians ∂F/∂x and ∂F/∂u can be taken directly.

source
GrowthParameterEstimation.Control.InputSchedule — Type
InputSchedule(change_times, values)

A piecewise-constant input schedule. values[i] (a scalar, or a vector with one entry per input) is applied from change_times[i] until change_times[i+1]; the last value is held to the end of the simulation. This is the form an optimal control solution takes when doses change only at decision times.

Examples

# 1 µM on days 6–12 of a 14-day horizon, decisions every 2 days
sched = InputSchedule(0:2:12, [0, 0, 0, 1.0, 1.0, 1.0, 0])

GrowthParameterEstimation.Control.simulate_schedule — Function
simulate_schedule(cm, x0, schedule, times; params = cm.params, solver = Tsit5(),
                  reltol = 1e-8, abstol = 1e-8) -> NamedTuple

Simulate the model under a piecewise-constant InputSchedule and return (success, times, states, outputs, inputs). states is n_states × length(times), outputs is n_outputs × length(times). The solver stops exactly at every input change, so jumps in the dose are resolved. Use it to replay a schedule chosen by an external optimizer, or comparator schedules such as constant dosing.

source
GrowthParameterEstimation.Control.schedule_ensemble — Function
schedule_ensemble(cm, x0, schedule, times; include_estimate = true, kwargs...) -> Vector

Replay one schedule on every parameter set from parameter_sets and return one simulate_schedule result per set. This is the robustness check for a schedule chosen with the point estimate: how far outcomes spread when the parameters are drawn from their bootstrap distribution.
